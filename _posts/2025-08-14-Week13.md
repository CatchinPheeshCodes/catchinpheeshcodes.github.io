### Introduction

My vision for this project was to create a themed boat ride in Unity, bringing focus to the intersection of technical skill and creativity.  I wanted to gain insight to some of the tools, methods, and difficulties of working with the creative tools that are used to bring story to life.  After spending the summer working in Unity, I can confidently say that the rumors are true.  Game development, or the development of any project within a popular engine, is extremely challenging.  I intended to gain exposure to tools that were unfamiliar to me this semester, expanding upon some of the foundational knowledge that I’ve amassed during this program including skillsets such as:

Computer Science Fundamentals: data structures, algorithms, object oriented programming, software engineering - best practices.
Unity: Learning new technologies. Exposure to and experience with a game engine. 
C#: Learning new programming languages. 

The key deliverables for this project were a blog that shows continuous commitment and progress, and a project that can be added to my portfolio with some polishing.  

### Background

My primary motivation for this project was to explore a personal interest in entertainment.  I wanted to gain fundamental exposure to the challenges of pursuing a technical career in an otherwise creative landscape.  Computer science is a broad topic with a variety of career paths to choose from.  We focus a lot of our time on fundamentals, as they lay an important foundation for any career.  I wanted themed entertainment or game development to be a part of my exploration, as I look beyond the completion of this program and consider what professional pursuits it may lead to.

Learning new skills is something that any professional developer can expect to do throughout the course of a long career.  In an effort to foster that mindset, I chose to focus on something challenging and unfamiliar to me.  This was a rewarding experience, despite the frustration.


### Methodology and Materials

The primary software that I utilized for this project was Unity, a popular gaming engine.  I quickly realized how difficult it would be to create something from scratch after opening a new project, and chose to focus on the learning materials that Unity provides.  The user interface for Unity is extremely detailed.  The control that the creator has seems endless and equally overwhelming at first.  The topics that I chose to focus on, within Unity’s learning tools, are:

Editor Essentials: This module provided an overview of the editor itself.  I learned how to navigate a scene, deploy assets, move assets around within the scene, and how the inspector can be used to control each individual asset that is deployed.
Programming Essentials:  This module provided a high level overview of the C# language, it’s use with Unity, and the Unity API.  
Unity Documentation: This was an extremely valuable resource, with detailed explanations of all things Unity.  
Aside from the learning materials that Unity provides, I also utilized the following tools:

YouTube: Can you learn anything new, without a couple of YouTube videos?  Although my final result differed, this is where I learned how splines can be created from scratch in Unity. 
C# Materials: A number of C# tutorials and articles were very helpful when trying to learn the syntax and best practices of using this language.
Khan Academy - Imagineering In A Box: I utilized this resource to understand the imagineering development pipeline.
ChatGPT - I used ChatGPT as a rubber duck when I was struggling to understand a concept or feature of Unity. 

### Results

Learning Objectives

Given the time allotted to this project, the end result is far less than what I had envisioned.  I underestimated the time that it would take to learn how to work within Unity and with a new language.  The visual appeal of my project is virtually non-existent.  There is a lot of work yet to do in order to make this into a viable candidate to showcase in interviews.  That said, I am confident that I achieved my learning objectives despite the relatively lackluster result of my efforts.  Here are the primary learning objectives that I started with at the beginning of the semester:

- Objective: Gain fundamental knowledge of a new programming language, C#.
This was achieved.  I created custom C# scripts for my water mesh, railing, and have started on a ride state machine that can be used to track the boat’s progress and trigger certain events that should occur along the ride path.

- Objective: Galvanize computer science fundamentals.
This was achieved.  Some examples are: the use of various data types, for loops, and conditional statements.  I made every attempt to follow best practices when using C#, as well.

- Objective: Portfolio expansion.
This was achieved.  I do have a project that can be showcased, but I would like to spend the additional time needed to implement a few more features and polish the visual appeal of the simulation.

Project Assessment

This was achieved.  The scene runs without error.  Something interesting that I learned early on, is that Unity compiles any change made to a script that is running within the scene when edits are saved.  If the script doesn’t compile, the simulation will not play.  This makes sense in hindsight, but I did spend some time finding a list of errors to work through after writing my first script.

### Discussion

I met my learning goals for this project, but fell short of what I had envisioned as a final result of  my efforts.  I am confident in the basic navigation and use of Unity, gained familiarity with the C# programming languages, and have established a solid foundation for the continuous development of the simulator that I had envisioned.  A commitment to learning how to use the tools that I chose to work with was critical in achieving these goals.  Rather than focusing on the visual appeal of my project, I chose to shift gears and focus on the technical aspects of what I wanted to do.  I feel confident that I have a solid foundation to build upon, in choosing to continue working towards what I had envisioned.

The time that was required to learn the complexities of Unity’s most basic of functions was the primary reason that I did not develop the simulation that I had intended to.  I also had not considered that I would need to learn how to use the C# applications that the Unity API provides, on top of learning the language itself.  In hindsight, I would have set more realistic expectations for what I expected to accomplish.  I value the idea of building something from scratch in an effort to learn new technologies, but underestimated how complex game engines really are.

### Conclusion

My greatest takeaway from this, is to continue learning new skills and to accept that it will take time to gain any true mastery of any given toolset.  I still have an interest in a technical career grounded in entertainment or game development, but have a much better understanding of how difficult it will be to go down that path.  Establishing a career as an engineer, learning to work in a technical setting, and fostering transferrable skills are much more attainable goals with respect to the immediate future.  What I foresee long term hasn’t changed, but the path that I take to get there is longer than I had imagined.
